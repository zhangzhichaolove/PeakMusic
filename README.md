# PeakMusic

开发中的整改目标与逐项验收：[整改清单](REMEDIATION.md)。

Android 音乐播放器，支持在线音乐、本地媒体库、后台播放与同步歌词。

## 当前能力

- 在线/本地音乐列表、收藏、最近播放和自定义歌单。搜索分为在线接口搜索与本地曲库筛选，支持取消旧查询、空状态和失败重试。
- 前台播放服务、MediaSession、系统媒体通知、音频焦点和耳机拔出暂停。
- 顺序播放、列表循环、单曲循环、随机播放、睡眠定时及系统均衡器入口。
- 播放队列、当前曲目和进度恢复。播放页队列入口支持下一首、上/下移、指定位置、移除、确认清空及定位当前曲目；编辑保留当前进度与暂停意图，分页避免一次拉取全部队列元数据。所有播放队列先写私有存储，只向服务传队列 ID；队列编解码和进度持久化在后台线程，暂停/清空可取消正在交接的请求。
- 播放页展示歌曲、歌手、封面和同步歌词，提供收藏、模式和固定底部播放控制。歌词自动居中、高亮，每首歌单独校准时间（±10 秒），区分无歌词和请求失败并提供重试。歌单支持重命名；收藏/历史/歌单曲目支持多选、全选、批量收藏/取消收藏和加入歌单，歌单内可批量移除成员。
- 首页不再串联弹出权限申请。本地音频在本地音乐页按需授权，支持手动刷新、前台媒体变化监听以及未授权/空库/扫描失败区分；通知及悬浮控制有独立设置入口。
- 本地页可按全部歌曲、歌手、专辑、文件夹浏览，显示分类数量并支持返回分类列表。点击某分类中的歌曲只播放当前可见分类队列；旋转后保留分类，新增/删除本地媒体自动刷新，不改写已经在播放的队列。
- 移除固定启动等待。首页侧边栏可修改、恢复及测试 API 地址，测试会检查真实列表端点、HTTP/业务状态及数据结构。
- API 诊断默认关闭，仅 Debug 手动开启且只在当前进程有效；有体积/保存时限、常见凭据脱敏和分享前确认，Release 禁止采集。详见下方隐私诊断说明。

## 构建要求

- JDK 17
- Android SDK 37
- Android Gradle Plugin 9.4.0


## API 约定

默认地址定义在 `ApiUrl.BASE_URL`，运行时可由用户修改。当前客户端只依赖：

```text
GET music/getMusicList?search=...
```

音乐数据沿用现有字段：`id`、`name`、`singer`、`img`、`lrc`、`mp3`。相对音频、封面和歌词地址按发起该请求的 API 基址解析；切换设置不会改变迟到响应或已保存曲目的归属。为兼容用户配置的局域网 HTTP 媒体服务，应用明确保留 HTTP 支持；生产环境建议使用 HTTPS。

## 外部依赖与发布说明

- 默认 Release 为未签名 APK；已支持环境注入版本/签名、实际证书与 R8 mapping 核验及不可覆盖归档。正式凭据由发布方提供，详见[发布与 CI 流程](docs/RELEASE.md)。
- 未接入崩溃监控或统计 SDK，也没有填写监控密钥。后续接入需要明确选型、隐私策略和有效密钥。
- 不假设服务端存在歌词以外的新字段或接口；需要服务端能力的功能应先确定接口契约。

## 体验回归

JVM 回归覆盖搜索防抖/取消/切换、扫描权限和失败、接口结构校验、无等待启动、歌词请求/偏移、播放/队列编辑与恢复、Room v1/v2→v3 迁移、源身份隔离、批量操作及失败回滚。

API 33+ **专用可丢弃模拟器**可运行 `scripts/verify-experience.sh emulator-5580`。脚本会清空此模拟器中 PeakMusic 的应用数据，并临时设置 200% 系统字体后恢复原值，故不用于已有个人数据的设备；仅接受 `emulator-*` 序列号。

原生用例通过 loopback HTTP 服务验证真实搜索请求、A→B 竞态、503 重试、本地分区及页面重建后范围保留；验证未授予音频/通知权限时首页和本地提示页仍可进入，不自动弹权限或悬浮窗设置。另验证真实静音音频播放、歌词重试和按歌曲偏移/收藏/模式、歌单重命名、横屏 200% 字体控制区以及队列排序/移除/清空/重建。另以 10,000 条元数据测试真实服务 IPC、恢复和播放，提交阶段有主线程磁盘访问检查。共 7 项原生用例，日志与截图保存在 `app/build/verification/experience/`。

尚需另做真机音频焦点、耳机、后台/息屏、完整深浅色与大字体巡检；模拟器 UI 通过不代表这些设备验收已完成。

## 混淆 Release 回归

`ANDROID_HOME=/path/to/sdk scripts/verify-queue-release.sh emulator-5580` 在专用模拟器上生成静音音频与 10,000 条队列、本机 loopback API，随后以默认调试证书签署 **Release APK 副本**并升级安装。平台原生测试 runner 验证混淆后的 API 响应列表、待接收队列恢复、稳定媒体键与独立音频 URL、按该键保存的歌词偏移、相对音频/歌词请求，以及选中曲目与 MediaSession 播放状态/时长。另实际打开混淆后的歌单页/ViewModel，点击多选、批量收藏、复制及移除，并用平台 SQLite 核对收藏/成员已提交且本地文件仍在，避免把 Debug 通过当成 Release 验收。

脚本会清空测试模拟器中的 PeakMusic 数据，结束时停止合成音频、关闭样本服务/端口转发并恢复 Debug 应用和常规测试 APK。日志及截图在 `app/build/verification/queue-release/`。此过程没有配置正式发布签名，也不会使用个人发布密钥。


## 数据源身份与旧数据

- API 来源使用规范化完整基址（协议、主机、端口、路径）的 SHA-256 命名空间，不用 CDN 域名判断来源。源内媒体 ID 接受数值或字符串，包含 ID 0；缺少 ID 才退回源内完整播放 URL。无 ID 的签名 URL 变化不作稳定身份保证，服务端应提供固定 ID。
- 同源同 ID 的收藏、历史、歌单成员和歌词校准共用身份键，音频 URL 是可变属性。不同 API 即使返回同 ID、同音频 URL，也独立记录；更换 API 基址视为另一来源，不擅自合并。
- Room v3 保留旧记录/主键/歌单外键关系；原在线记录未知来源标记为“旧记录（来源未知）”，旧 URL 校准仍属于这些记录，不自动移交到新 API。已有本地标识由 local 字段确认，继续沿用 MediaStore Uri/原路径键，不丢旧本地收藏及歌单成员。
- `MusicTrackEntity.source` 因兼容数据库沿用历史列名，但现在表示**稳定库键**，不是音频地址；播放、分享、下载及打开文件一律使用 `getPlaybackUrl()`。新增 sourceId/sourceBaseUrl/mediaId/playbackUrl 与队列 JSON 一起持久化，API JSON 不能写入客户端来源或已存库键。
- 选中曲目的服务回调仅传一条完整元数据，不传全队列。首页/播放页不再按 URL 从当前在线列表反查曲目，避免共享 URL 时串封面/歌词；队列恢复优先按身份键和位置，兼容旧 URL/索引状态。
- 收藏/歌单/搜索结果显示来源，长按菜单显示完整来源。再次播放或对最新接口曲目执行收藏/添加歌单等写入时更新已存地址；尚无按 ID 获取详情或续签的服务端端点，旧收藏的过期 URL 不会被客户端自行续签。
- `scripts/verify-sources.sh emulator-5580` 验证真实迟到响应、双源同 URL 的独立收藏/歌单、当前曲目 IPC 与歌词偏移、签名 URL 更新、服务重建后暂停于 12 秒。它保留旧数据以便检查迁移，但会新增合成记录，仅用于可丢弃模拟器。与 7 项常规体验回归合计 8 项原生用例，证据位于 `app/build/verification/sources/`。

## 曲库批量操作

- 曲目页工具栏进入“多选”，点曲目或复选框选择，不触发播放；支持全选/取消全选，返回键先退出选择。未进入多选时保留原长按菜单。
- 批量操作使用稳定库键重新读取最新元数据，在一个 Room 事务中校验完整集合、去重并写入。任何曲目/目标歌单失效或 SQLite 写入异常时不部分提交；不会用旧列表的签名 URL 覆盖新地址。
- 取消收藏和从歌单移除均需确认。移除只删除当前歌单关系，不删除音乐文件、其他歌单、收藏或播放历史；加入歌单是复制成员，不是移动文件。
- 配置重建（例如旋转）保留已选曲目和进行中的操作。失败后解锁并保留仍存在的选择，可重试；成功后退出选择并刷新。临时选择只保存在 ViewModel，进程被系统回收后退出选择，避免把大量曲目键放进 Bundle/Binder。
- 选择变化用局部 checkbox payload 更新，不重载封面或通知整份数据失效。
- `scripts/verify-library-batch.sh emulator-5580` 运行 2 项真实 UI/Room 回归：双来源同 URL、复选框/全选、页面重建、收藏/取消收藏、复制/移除、元数据及历史/文件保留，以及事务阻塞期间重建、注入失败后回滚与重试。脚本不清空曲库，只清理自身临时数据；仍仅用于可丢弃模拟器，会停止本应用播放服务。
- 批量日志和截图在 `app/build/verification/batch/`；加上下面的本地分类回归，当前音乐合计 **123 项 JVM、13 项原生用例**（7 常规 + 1 来源 + 2 批量 + 1 本地分类 + 2 诊断），另有真正混淆 Release 黑盒验证。

## 本地分类浏览

- 分类仅使用已授权的 MediaStore 扫描快照，不遍历整个文件系统。后台构建歌手/专辑/文件夹索引，组内沿用扫描顺序，并按媒体 Uri 去重。
- 有专辑 ID 时使用“存储卷 + 专辑 ID”区分同名专辑；无 ID 时退回专辑名和歌手组合。元数据不完整时不声称能推断真实专辑身份；未知歌手/专辑/文件夹有明确分类。
- Android 10+ 使用 `VOLUME_NAME` 与 `RELATIVE_PATH` 生成完整目录标识，即使没有原始 DATA 路径也可浏览；旧系统退回已提供文件路径的父目录。同名末级目录、不同存储卷不会因为名字相同被合并。
- 分类和选中组只保存小型导航字段，重建时重新读取扫描快照，不把整份曲库塞进 Bundle。当前分类被删空后显示空状态与返回入口；撤回读取权限会清除可见曲库并使在途索引结果失效。
- 本地播放直接提交已显示列表的快照和选中位置，避免分类位置误索引全部歌曲，也避免异步刷新导致点到另一首。分类返回使用系统 Back 或页面返回按钮；长按仍可打开原有详情/收藏/加入歌单菜单。
- `scripts/verify-local-library.sh emulator-5580` 需要 FFmpeg 和 API 33+ 可丢弃模拟器，生成 3 份带标签的静音 MP3，写入自身 MediaStore 测试行，实际浏览、解码播放、旋转后新增/删除媒体并核对队列不变。结束删除自身测试媒体/历史并恢复 API 偏好和原音频权限，不清空既有曲库；此脚本会清空当前测试播放队列，仅用于可丢弃设备。生成的 MP3 已排除在 Git 跟踪之外。
- 日志及截图在 `app/build/verification/local/`。混淆 Release 脚本也需要 FFmpeg，平台独立 runner 直接浏览真实专辑/文件夹/歌手并解码本地 MP3，核对分类队列只有 2 首，返回 `RELEASE_LOCAL_LIBRARY_OK`。硬件/OEM、所有页面的深浅色与大字体专项仍待单独验收。

## 隐私友好的 API 诊断

- 诊断采集**默认关闭，仅 Debug 可手动开启，且只在当前进程有效**；重启进程自动关闭，旋转页面不重新授权。Release 入口可查看已有脱敏缓存，但不允许开启采集，不自动上传。
- 请求仅记录方法、无用户信息/路径/查询参数/片段的 origin、请求编号、收到响应头的耗时，以及 HTTP 状态和已知正文大小；不记录请求头、请求正文或网络异常消息，不把响应正文/URL 打印到 logcat。
- 最多旁读 1 MiB 正文（额外 1 字节用于判断超限），递归过滤常见 token、密码、Cookie、签名、个人信息字段；URL 只保留 origin，过滤 Bearer/Basic、JWT、嵌入的序列化 JSON 和常见本地路径。非 JSON、损坏、过深/过于复杂或超限正文只保存省略说明。
- 这是**有限规则脱敏，不是匿名化保证**；自定义字段、媒体名称或主机名仍可能包含私人信息。复制正文/分享均先显示检查提示，剪贴板在支持的系统标记为敏感。预览与正文复制上限 65,536 字符，较大内容提示通过文件分享。
- 原始响应体不被消费或替换，清空/淘汰诊断文件不影响 Retrofit/OkHttp 读取完整原始响应；诊断存储失败不使成功请求失败。关闭采集或清空会使先前在途采集票据失效，迟到响应不会重新生成已清空日志。
- 脱敏记录位于私有 `cache/diagnostics-v1`；分享前再次脱敏，并在 `cache/diagnostic-exports` 创建独立快照。FileProvider 仅暴露导出目录，存储目录和旧 `api-response-logs` 原文目录不再提供 URI；升级后启动/访问时后台删除旧原文文件。
- 两个目录各限 20 个文件/20 MiB，单条记录/导出各限 2 MiB，24 小时过期；启动及下一次存储访问时清理，不在应用停用时运行定时删除。读取/导出也检查过期，停留页面的旧选择不会续存过期日志。“清空”删除当前记录与本应用的导出快照，已由接收方另存的副本不受影响。
- 页面文件列表/读取/格式化/导出在后台执行，诊断页独立适配深浅色动作文字对比度和系统栏避让。复制确认期间退到后台再返回，仍使用用户点选时的脱敏快照，避免刷新选择引起崩溃。
- `scripts/verify-diagnostics.sh emulator-5580` 用真实 loopback HTTP、原生页面、剪贴板和 FileProvider 验证默认关闭、手动采集、原始字节完整、大响应省略、清空后迟到响应、复制/分享前确认及重建。分享 chooser 被测试拦截，**没有实际向其他应用或服务器发送诊断**。脚本仅接受可丢弃 API 33+ 模拟器，清空诊断缓存并恢复剪贴板，不清空媒体库；日志和深浅色截图位于 `app/build/verification/diagnostics/`。
- 真正混淆 Release 黑盒另外验证采集开关关闭且不可启用、旧原文清理、旧 FileProvider root 拒绝读取；返回 `RELEASE_DIAGNOSTIC_PRIVACY_OK`。这是测试证书签署的 APK 副本，不是正式发布签名。

## 发布与 CI

- `scripts/package-release.py` 从环境读取完整发布版本/签名配置；构建、单测、Debug/Release Lint 后验 APK 内部版本、非 debuggable、期望证书和 R8 mapping 正文/DEX 身份，归档 APK、mapping、Git/版本清单及 SHA-256，不自动上传或发版。
- `python3 -m unittest discover -s scripts/tests -v` 运行 8 项打包策略测试；`scripts/verify-release-config.py` 用一次性测试证书验证真正 Gradle 签名/版本注入及失败路径，结束恢复默认构建产物。测试归档标为 TEST-ONLY，不能作为正式发布凭据。
- `scripts/verify-native-ci.sh emulator-5580` 汇总本项目全部常规原生与混淆 Release 用例，仅用于可丢弃 API 33+ 模拟器。GitHub 工作流增加 API 33/36 原生矩阵及独立的手动签名归档入口；远端执行和正式发布环境尚待仓库持有方配置、验收。
- 密钥输入、版本约束、长期映射保存、Actions environment/Secret 说明及命令见[发布文档](docs/RELEASE.md)。
